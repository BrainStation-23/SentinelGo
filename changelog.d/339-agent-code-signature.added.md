- macOS: the inventory's `mdm` block now carries the agent's own code signature and Full Disk Access state, `mdm.agent` (#339), so the server can build the Full Disk Access grant (a PPPC profile) for each Mac from what that Mac reports, without anyone typing in a bundle ID or team ID (Compliance-OS#530). `code_signature` has `path` (the app bundle when the agent runs from one, else the executable), `identifier`, `team_id` (only for a Developer ID signature, else null), `signature` (`developer_id`, `adhoc`, `unsigned`, or `other` for an Apple-issued certificate that isn't Developer ID) and `designated_requirement` (the same text as `codesign -d -r-`). They're read from the running process through Security.framework (`SecCodeCopySelf`, through purego); a Developer ID signature is recognised by checking the code against Apple's Developer ID requirement. `full_disk_access` is `granted`, `denied` or `unknown`, checked on every inventory, so a grant or revocation shows up without a restart. The block is left out on Windows and Linux. `sentinelgo mdm status` shows the signature and path.
