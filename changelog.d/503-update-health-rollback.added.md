- Updates: an upgrade rolls back on its own when the new version doesn't work (#503). The agent keeps `<exe>.backup` and writes `update_marker.json` next to the config. Before restarting, it starts a watchdog: a copy of the old binary running `sentinelgo update-watchdog`, as a transient systemd unit on Linux, in its own session on macOS, or as a detached process on Windows. The new version starts its own watchdog if none is running, for example after a reboot. It is healthy once it has signed in and uploaded agent info, and then it deletes the marker and the backup. Otherwise, 10 minutes after its latest start or after more than 3 starts, the watchdog restores the backup and restarts the service. A new version that is running but offline, while the watchdog can't reach the server either, gets more time, for up to 24 hours. A version that was rolled back is skipped until the server offers another one. The restored agent logs the rollback, so it shows up in the uploaded agent log, and the watchdog logs to `update_watchdog.log`. While an upgrade waits for its health check, the agent doesn't start another one. Server-approved downgrades (#505) aren't watched.
